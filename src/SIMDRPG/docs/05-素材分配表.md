## 2. 怎么用那些数字命名的文件

`objects/`、`backgrounds/`、`fx/` 里有一堆 `1.png` `2.png`。
它们是原素材包里的编号，看不出是什么。

**办法**：打开 `_contact_objects.png` / `_contact_backgrounds.png` / `_contact_fx.png`，
网格里标了文件名，扫一眼就知道哪个是药水、哪个是炸弹。

**策略**：不要逐个手写映射，用**分类扫描**解决。

### 2.1 按尺寸自动分类（推荐）

小图（≤32×32）= 图标/道具；大图（≥256）= 背景。
写 20 行脚本就能自动分：

```python
# 思路示例（本项目未附带此脚本，你要的话自己写 20 行）
for f in files:
    w, h = png_size(f)
    if w >= 200 or h >= 200: bucket = "background"
    elif w <= 32 and h <= 32: bucket = "icon"
    else: bucket = "prop"
```

### 2.2 直接整目录挂载（最省事）

配置表里写**目录 + 索引范围**，游戏启动时扫描目录全部加载：

```cpp
// 启动时把 objects/ 全部加载，随机分配到掉落表
for (auto& p : std::filesystem::directory_iterator("assets/gfx/objects"))
    if (p.path().extension() == ".png")
        g_item_pool.push_back(load_png(p.path().string()));
```

**这样 440 个道具一个不漏地进了掉落池**——玩家每次开箱子都是惊喜，
而且你不用给每个起名字。

> 这就是"全部用上"最省力的做法：**池化**。
> 不需要每个素材都有精确语义，让程序随机分配也是一种设计。

### 3.1 `terrain/`（22）— 六张地图的地面

| 文件 | 用在哪 |
|------|--------|

| `terrain_spring.png` | 远古兽巢 |
| `terrain_winter_ice.png` | 霜噬山道的冰面（第二层） |
| `trees_{spring,summer,autumn,winter}.png` | 各地图的树（装饰层，带碰撞） |
| `plants_*.png` | 灌木（装饰层，可穿过） |
| `wildflowers_*` / `flowers.png` | 草地点缀 |
| `mushrooms.png` | 森林/地窖的发光蘑菇 |
| `cliff_{summer,autumn,winter}.png` | 山道两侧的岩壁 |
| `Rocks, Grasslands.png` | 兽巢的巨石 |
| `Waterfall.png` | 山道的瀑布（动画：切帧） |
| `ice-shallows.png` | 冰河浅滩 |
| `tilled_soil.png` | 村庄的农田 |

**关键索引**（四季通用）：`17`=纯地面、`177`=水、`26`=沙土/路、`250`=石/建筑。

**关于树**：当前版本**没有用 `trees_*.png` 图集**。
树是用 `terrain_*` 里"纹理最强的植被 tile"填的（`gen_maps.py` 的
`T_TREE_SUMMER=119` / `T_TREE_AUTUMN=190` / `T_ROCK_SPRING=353`）。
这样"撞上去有感觉"（看得见），但只是"有纹理的地面"，不是立体的树。

要接真正的树，得加一层贴图：地图格式加 `[DECOR]` 段，
`draw_world` 之后按 `decor[y][x]` 从 `trees_*.png` 取一格画上去。
**这是本项目最值得做的下一个改进。**

### 3.3 `chars/`（22 + 168）— 角色

### 3.4 `monsters/`（50）— 28 种敌人

见 `00-世界观与六张地图.md` 第 4 节的完整表格。分配原则：

- **中世纪系**（goblin/skeleton/bat/snake/slim/cyclop/dragon/leonard）→ 森林、山道、地窖
- **史前系**（tyrannosaurus/pterodactyl/turtle/lizard/insect/plant）→ 兽巢

## 5. 验收：怎么确认"全部用上了"

写个 30 行的脚本，扫 `assets/gfx` 的每个 PNG，
去代码里 grep 文件名（或目录名），列出**没被引用的**：

```python
import os, subprocess
used = subprocess.run(["grep","-rho",r"[a-zA-Z0-9_./-]*\.png","src/","include/"],
                      capture_output=True, text=True).stdout
unused = []
for root,_,fs in os.walk("assets/gfx"):
    for f in fs:
        if f.endswith(".png") and not f.startswith("_contact"):
            rel = os.path.join(root,f).replace("\\","/")
            # 目录被整挂载的算已用
            if os.path.basename(os.path.dirname(rel)) in ("objects","fx","backgrounds"):
                continue
            if f not in used:
                unused.append(rel)
print(f"未引用: {len(unused)}")
for u in unused[:30]: print("  ", u)
```

**目标：`未引用 = 0`。** 跑到 0 就证明全部素材都进游戏了。

## 6. 如果还是觉得某些素材没处放

三个兜底用法，任何一个都能吃掉几十个素材：

1. **做成"收藏品"系统**：地图上散落可拾取的图鉴条目，拾取后在主菜单图鉴里展示。
   —— 440 个道具全部变成收集要素。
2. **做成随机装饰**：地图加载时随机往地面上撒 N 个装饰 sprite（不参与碰撞）。
3. **做成主菜单背景**：切图时的加载画面，轮播所有背景图。

> 独立游戏里这种"素材回收"很常见。
> 玩家不会觉得你在偷懒，他们会觉得"这游戏内容真多"。
