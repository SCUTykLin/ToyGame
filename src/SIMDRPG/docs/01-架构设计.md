## 1. 分层

```
┌──────────────────────────────────────────────────────────┐
│  game/        玩法层：剧情、任务、AI、战斗、物品          │
│               你 90% 的时间花在这层                        │
├──────────────────────────────────────────────────────────┤
│  ui/          界面层：ImGui 面板、编辑器、输入映射        │
│               不含玩法，也不直接改数据（改数据走 world）  │
├──────────────────────────────────────────────────────────┤
│  world/       世界层：地图、相机、天气、碰撞查询、编辑逻辑  │
├──────────────────────────────────────────────────────────┤
│  ecs/         实体层：Component / Entity / Registry       │
├──────────────────────────────────────────────────────────┤
│  gfx/         渲染层：Atlas、Blitter、Renderer、Font       │
├──────────────────────────────────────────────────────────┤
│  simd/        内核层：标量/SSE2/AVX2 三套混合实现          │
├──────────────────────────────────────────────────────────┤
│  platform/    平台层：窗口、输入、时钟（唯一碰 SDL 的地方）│
├──────────────────────────────────────────────────────────┤
│  core/        基础层：Vec2、Rect、Pixel、Concepts、Log     │
└──────────────────────────────────────────────────────────┘
```

**铁律：箭头只能朝下。** `core` 不知道 `gfx` 存在，`gfx` 不知道 `game` 存在。
违反这条，半年后你就没法改动任何东西了。

### 为什么这么分

| 层 | 变更频率 | 如果要改 | 影响范围 |
|----|---------|---------|---------|
| `game/` | 每天 | 加个敌人、改句台词 | 只有自己 |
| `ui/` | 每周 | 加个面板、改布局 | 只有自己 |
| `world/` | 每周 | 加地图、改天气 | game / ui |
| `gfx/` | 每月 | 换渲染方式 | 全局，但很少动 |
| `simd/` | 一次性 | 加 AVX-512 后端 | 只有 gfx |
| `platform/` | 几乎不动 | 换 SDL3 / 换窗口库 | 只有 main |

## 2. 三个关键决策（以及为什么）

### 决策一：软件渲染，不用 `SDL_Renderer` 画精灵

**放弃**：`SDL_RenderCopy` / `SDL_Texture` / GPU 加速。

**换来**：
- 你能拿到 `uint32_t*` 帧缓冲，自己决定每个像素怎么算
- SIMD 有地方用（GPU 那边你只能写 shader）
- 可以自由实现「颜色调制」「雾」「光照叠加」这类效果，不用写 shader

**代价**：
- 2048×1536 的地图，全屏 1280×720，每帧要写 92 万像素
- 必须自己处理裁剪、混合、缩放

> 这就是本项目的意义：**用可以接受的低效，换一次彻底理解像素管线**。

SDL 只负责三件事：开窗口、收键盘、把最后一帧 `SDL_UpdateTexture` + `SDL_RenderPresent`。

### 决策二：自有 `Surface`，不用 `SDL_Surface`

```cpp
struct Surface {
    uint32_t* pixels;   // 0xAARRGGBB，行主序
    int       w, h;
    int       pitch;    // 每行像素数（可能 > w，用于对齐）
};
```

**为什么不用 `SDL_Surface`**：
1. `SDL_Surface` 的 `pitch` 是 SDL 定的，你不能保证 16 字节对齐 → SIMD 只能走 `loadu`，慢一档
2. 你需要精确控制像素格式（`0xAARRGGBB`），不想被 SDL 的格式转换坑
3. 后处理（雾、暗角）需要能自由读写任意像素

**对齐要求**：`pixels` 必须 32 字节对齐（AVX2 要求），`pitch` 必须是 8 的倍数（8 个 uint32 = 32 字节）。

```cpp
// 分配时用 _aligned_malloc( size, 32 )  （MSVC）
//          posix_memalign( &p, 32, size )（Linux/macOS）
```

### 决策三：ECS，但**不用**第三方库

自己写一个最小的：

```cpp
registry.create()
    .add<Transform>(x, y)
    .add<Sprite>(atlas, frame)
    .add<Health>(100);
```

模板元编程的用处就在这儿：`add<T>` 需要在**编译期**给每个组件类型分配一个 ID，
运行时用 `bitset<32>` 判断有没有。这是你在 `Roguelike/ECS/ECS.h` 里已经写过的思路，
这次用 C++20 concepts 重写一遍，会干净很多。

---

### 决策四：界面单独一层，编辑逻辑不许写在面板里

阶段 24 要加一个"游戏里按 F2 弹出编辑器"。它天然会引诱你写成
"一个 `Editor` 类，既画面板又改地图"—— **不要**。

按这张图拆：

```
Game（装配）
 ├── ui/EditorUi        只画 ImGui 面板，只发"意图"
 └── world/EditSession  只改 TileMap/PropSet，不认识 ImGui
```

判断标准很土，但有效：

- 在 `ui/` 的文件里 grep `map_->paint`、`props_->set_`、`scan(` ——
  一个都不该有；
- 在 `world/EditSession` 里 grep `ImGui`、`SDL_` —— 同样一个都不该有。

好处不是"看起来整齐"，而是**编辑规则能无头测试**：
`tests/session_test.cpp` 不开窗口就能验证"画一笔、撤销、落笔刷碰撞、存盘重读"。
如果逻辑在面板里，你只能靠肉眼看。

> `ui/` 和 `game/` 是平级，但 `ui/` **不许** include `game/`。
> 这样 Game 里的玩法怎么改，都不会把编辑器带崩。

## 3. 数据流

一帧的生命周期：

```
[platform]  键盘状态 ──┐
                        ├──> [game] 玩家意图（方向、攻击、交互）
[world]     地图/碰撞 ──┘         │
                                   ▼
                        [ecs] 更新所有系统
                         ├─ 移动系统：位置 += 速度 * dt，撞墙则回退
                         ├─ 动画系统：帧计时器推进
                         ├─ AI 系统：状态机
                         └─ 战斗系统：生成 HitBox
                                   │
                                   ▼
                        [gfx] Renderer 发出绘制请求
                         ├─ draw_map(camera)      → 地面层 tile
                         ├─ draw_entities()       → 按 y 排序的精灵
                         ├─ draw_weather()        → 雨/雪粒子
                         └─ draw_ui()             → 血条/对话框
                                   │
                                   ▼
                        [simd] Blitter 逐批混合像素
                                   │
                                   ▼
                        [platform] SDL_UpdateTexture → 上屏
```

**注意**：`game` 层只往 `Renderer` 里塞「绘制请求」，**不直接碰像素**。
这样你以后想把 `Blitter` 换成 OpenGL，`game` 一行都不用改。

## 5. 关键接口（先定契约，再写实现）

不要一上来就写 `Blitter.cpp`。**先把这些签名抄到头文件里**，
让编译先过，再一个个填 —— 这叫「空壳先行」，能逼你想清楚接口。

### 5.1 `core/Types.h`

```cpp
namespace core {
    struct Vec2i { int x, y; };
    struct Vec2f { float x, y; };
    struct Rect  { int x, y, w, h; };

    // 像素：内存布局 0xAARRGGBB
    using Pixel = uint32_t;

    constexpr Pixel rgba(uint8_t r, uint8_t g, uint8_t b, uint8_t a = 255) {
        return (Pixel(a) << 24) | (Pixel(r) << 16) | (Pixel(g) << 8) | b;
    }
    constexpr uint8_t alpha_of(Pixel p) { return p >> 24; }
    constexpr uint8_t red_of  (Pixel p) { return (p >> 16) & 0xFF; }
    constexpr uint8_t green_of(Pixel p) { return (p >>  8) & 0xFF; }
    constexpr uint8_t blue_of (Pixel p) { return  p        & 0xFF; }
}
```

### 5.2 `gfx/Surface.h`

```cpp
namespace gfx {
    class Surface {
    public:
        Surface(int w, int h);              // 分配 32 字节对齐的缓冲
        ~Surface();
        Surface(const Surface&) = delete;   // 禁止拷贝，避免双重释放
        Surface& operator=(const Surface&) = delete;
        Surface(Surface&&) noexcept;        // 允许移动

        Pixel*       data()       { return px_; }
        const Pixel* data() const { return px_; }
        int  width()  const { return w_; }
        int  height() const { return h_; }
        int  pitch()  const { return pitch_; }

        void clear(Pixel color);
        Pixel* row(int y) { return px_ + y * pitch_; }

    private:
        Pixel* px_ = nullptr;
        int w_ = 0, h_ = 0, pitch_ = 0;
    };
}
```

### 5.3 `gfx/Blitter.h`（★ 最重要）

```cpp
namespace gfx {
    // 注意：参数统一是 const Surface&，不是 Atlas。
    // Atlas 负责"图集 + 矩形"这一层语义，Blitter 只认像素缓冲和矩形 ——
    // 这样 Blitter 不需要知道图集的存在，耦合更小。
    // 调用方：blit_alpha(fb, atlas.image, atlas.frame(i), x, y);

    // 源图不透明区域直接覆盖（内部其实是 memcpy，见 03 阶段 4）
    void blit_opaque  (Surface& dst, const Surface& src, Rect srcRect, int dx, int dy);

    // 带 alpha 混合：dst = src*a + dst*(1-a)
    void blit_alpha   (Surface& dst, const Surface& src, Rect srcRect, int dx, int dy);

    // 先给源图整体乘一个颜色（天气/光照/受击闪白）
    void blit_tinted  (Surface& dst, const Surface& src, Rect srcRect, int dx, int dy, Pixel tint);

    // 注：这里**不提供** blit_colorkey（颜色键透明）。
    // 因为 LPC 和 superpowers 的素材都带 alpha 通道，不需要"把某个颜色当透明"。
    // 如果你的素材是 RGB + 洋红底色，再自己加一个 —— 逻辑很简单：
    //   遇到 src == key 就跳过，否则按 alpha 混合。

    // 最近邻缩放（怪物素材尺寸差异极大，靠它统一到目标框）
    void blit_stretch (Surface& dst, const Surface& src, Rect srcRect, Rect dstRect);

    // 用源的 alpha 当遮罩、用 color 当颜色（忽略源 RGB）。
    // 字体、图标染色用它。和 blit_tinted 的区别：
    //   tinted 是"乘"，源本身是深色就永远涂不亮；
    //   mask   是"换"，只借形状。
    void blit_mask    (Surface& dst, const Surface& src, Rect srcRect, int dx, int dy, Pixel color);

    // 整块填色（UI、雨天压暗）。**直接写像素，不看 alpha**。
    void fill_rect    (Surface& dst, Rect r, Pixel color);

    // 半透明整块填充（雾、暗角、编辑器网格）。逐像素混合，比上面那个慢。
    void fill_rect_alpha(Surface& dst, Rect r, Pixel color);

    // 单像素混合（UI / 特效 / 雨滴）
    void blend_pixel_scalar(Pixel& d, Pixel s);
}
```

> **为什么分成这么多函数而不是一个带 flags 的？**
> 因为 SIMD 的代码路径必须**尽量短、分支尽量少**。
> 一个函数里塞 4 种模式，编译器没法把内层循环优化好。
> 拆开之后每个函数都只有一条直线路径，向量化才彻底。

### 5.4 `simd/Backend.h`

```cpp
namespace simd {
    enum class Isa { Scalar, SSE2, AVX2 };

    Isa detect();                                   // CPUID 探测
    Isa active();                                   // 当前生效的后端

    // 运行时派发：每个函数内部 switch，编译器内联不了就用函数指针表
    void blend_row_sse2(Pixel* dst, const Pixel* src, int n);
    void blend_row_avx2(Pixel* dst, const Pixel* src, int n);
    void blend_row_scalar(Pixel* dst, const Pixel* src, int n);

    inline void blend_row(Pixel* dst, const Pixel* src, int n) {
        switch (active()) {
            case Isa::AVX2:   return blend_row_avx2(dst, src, n);
            case Isa::SSE2:   return blend_row_sse2(dst, src, n);
            default:          return blend_row_scalar(dst, src, n);
        }
    }
}
```

**注意 `n` 是「像素个数」，不是字节数。** 这个约定要在所有 SIMD 函数里统一，
否则你会在第 3 天写出一个越界写，然后调 4 小时。

## 6. 模板元编程的四个落点

C++20 的模板不是炫技，本项目只在四个地方用它，每一处都解决真实问题：

### 落点 1：编译期组件 ID

```cpp
template <typename T>
inline ComponentId component_id() {
    static const ComponentId id = next_id();
    return id;
}
```

同一个 `T` 在整个程序里只拿到一个 ID，且只在第一次调用时分配。
比 RTTI 快、比字符串哈希稳。

### 落点 2：类型安全的 `add<T>` / `get<T>`

```cpp
template <typename T, typename... Args>
T& Registry::add(Entity e, Args&&... args) {
    static_assert(std::is_base_of_v<ComponentBase, T>, "T 必须是组件");
    ...
}
```

写错类型，**编译期就报错**，而不是运行时返回空指针。

### 落点 3：用 `concept` 约束 SIMD 后端

```cpp
template <typename B>
concept SimdBlendBackend = requires(Pixel* d, const Pixel* s, int n) {
    { B::blend_row(d, s, n) } -> std::same_as<void>;
    { B::lane_width }        -> std::convertible_to<int>;
};
```

以后加 AVX-512 后端，只要满足这个 concept 就能直接插进去，编译器替你验收。

### 落点 4：fold expression 调度系统

```cpp
template <typename... Systems>
void run_systems(Registry& reg, float dt, Systems&&... sys) {
    (sys(reg, dt), ...);   // 一行展开所有系统
}
```

## 7. 你不该做的事

| 别做 | 因为 |
|------|------|
| 在 `game/` 里 `#include <SDL.h>` | 平台层会被你捅穿，以后换库要改 50 处 |
| 用 `SDL_Texture` 存精灵 | 拿不到像素，SIMD 白学 |
| 一个 `Game.cpp` 写 3000 行 | 你在 `Worms/gameLoop.cpp` 已经吃过这个亏了 |
| 一开始就上 AVX2 | 先用标量写对，再用 SSE2 对照，最后 AVX2。顺序反了你会调不出来 |
| 用 `float` 存屏幕坐标 | 像素是整数，浮点累积误差会让精灵抖 |
