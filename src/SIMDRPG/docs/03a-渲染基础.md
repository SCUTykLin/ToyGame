## 阶段 0 · 窗口

### 0.1 这一阶段要解决什么

你要的东西最终是一块内存里的像素数组，但**人看不见内存**。
所以第一件事是把这块内存接到屏幕上：开一个窗口，把数组推上去。

这一阶段只做这件事。屏幕上出现一个渐变，就算过。

### 0.2 必须先想清楚：两个分辨率

这是新手最容易混的一点，混了之后所有坐标都会错。

| 名字 | 值 | 谁在用 |
|------|-----|--------|
| **窗口分辨率** | 1280×720 | 操作系统、窗口本身 |
| **内部分辨率** | 640×360 | 你的所有绘制代码、`Surface`、碰撞、相机 |

**你只画 640×360**，SDL 负责把它放大到 1280×720。
为什么这么做：

1. 每帧只处理 23 万像素，不是 92 万——SIMD 的压力小 4 倍。
2. 像素感更强。32×32 的 tile 在 640×360 下是 32 像素，放大 2 倍后是 64 像素的方块，
   看起来是"像素游戏"；直接在 1280×720 下画，同样的 tile 只有 32 像素，看起来是"小图"。
3. 以后想改分辨率，只改这一个常量。

代码里我用 `WIN_W/WIN_H` 和 `INT_W/INT_H` 两组常量区分，**永远不要混用**。

### 0.4 `include/platform/Window.h`

<!-- FILE: include/platform/Window.h -->
```cpp
#pragma once
#include <cstdint>

namespace platform {

// 窗口 + 渲染器 + 一张流式纹理。
//
// 设计要点：头文件里**不出现 <SDL.h>**。
// 用一个不透明的 Impl 指针把 SDL 类型藏进 .cpp，
// 这样 gfx / game 层 include 这个头时，不会被迫也 include SDL。
class Window {
public:
    // win_w/win_h      : 窗口在屏幕上的大小
    // internal_w/h     : 你实际绘制的分辨率
    Window(int win_w, int win_h, int internal_w, int internal_h, const char* title);
    ~Window();

    // 管着 SDL 资源，拷贝会导致双重释放
    Window(const Window&) = delete;
    Window& operator=(const Window&) = delete;

    // ---------------------------------------------------------------
    // 一帧的绘制顺序（接了 ImGui 之后）
    //
    //   begin_scene(pixels, pitch)  上传游戏画面 + 清屏 + 画上去
    //   ... ImGui 在这里画 ...
    //   present()                   SDL_RenderPresent
    //
    // 拆成两半是因为 ImGui 必须画在"游戏画面之上、Present 之前"。
    // 老版只有一个 present()，把三步焊死了，加 UI 时只能整个改。
    // ---------------------------------------------------------------
    void begin_scene(const uint32_t* pixels, int pitch_pixels);
    void present();

    // 兼容旧写法：上传 + Present（不画 UI）。
    void present(const uint32_t* pixels, int pitch_pixels);

    // 把当前窗口的像素读回来（含 ImGui 画的内容）。
    // 必须在 present() 之前、画完之后调 —— present 之后 backbuffer 可能是空的。
    bool read_pixels(uint32_t* dst, int dst_pitch_pixels) const;

    // 处理事件。返回 false 表示该退出了（点了关闭或按了 ESC）
    bool poll();

    // ---------------------------------------------------------------
    // 给 UI 层（ImGui）用的三个口子
    //
    // 为什么返回 void* 而不是 SDL_Window*：这个头文件仍然不 include SDL。
    // 调用方（ImGuiLayer）自己 include <SDL.h> 再 static_cast 回去。
    // ---------------------------------------------------------------
    void* native_window()   const;
    void* native_renderer() const;

    // 事件过滤器：在游戏处理之前把每条事件给 UI 看一眼。
    // 返回 true = UI 吃掉了（比如正在输入框里打字），游戏别再处理。
    //
    // 参数是 const SDL_Event*，但这里只能写成 const void* ——
    // 头文件不认识 SDL_Event。
    using EventFilter = bool (*)(const void* sdl_event);
    void set_event_filter(EventFilter f) { filter_ = f; }

    int internal_width()  const { return iw_; }
    int internal_height() const { return ih_; }

    // 窗口在屏幕上的实际尺寸。
    // 鼠标事件报的是**窗口**坐标，而画面上的一格是**内部**坐标，
    // 两者差一个缩放比：窗口 1280×720 显示 640×360 的画面，差 2 倍。
    // 编辑器要靠这个换算，否则点哪儿画哪儿会偏移一倍。
    int window_width()  const { return ww_; }
    int window_height() const { return wh_; }

private:
    struct Impl;                 // 定义在 .cpp 里
    Impl* impl_ = nullptr;
    int iw_ = 0, ih_ = 0;
    int ww_ = 0, wh_ = 0;        // 窗口尺寸（屏幕像素）
    bool running_ = true;
    EventFilter filter_ = nullptr;
};

} // namespace platform
```

**三个决定，都要理解**：

1. **为什么用 `Impl*` 而不是直接写 `SDL_Window*`**
   `SDL_Window` 是 SDL 的类型，头文件里出现它就必须 `#include <SDL.h>`。
   于是每一个 include 了 `Window.h` 的文件都会拖进整个 SDL 头文件树（编译变慢），
   而且 SDL 的宏（比如 `main`）会污染所有翻译单元。
   这个手法叫 **pimpl（pointer to implementation）**。

2. **为什么不用 `std::unique_ptr<Impl>`**
   可以用，但 `unique_ptr` 的析构函数需要 `Impl` 的**完整定义**。
   而 `Impl` 定义在 .cpp 里，头文件里它是不完整类型。
   解法是在 .cpp 里显式定义 `Window::~Window() = default;`。
   两种都行，这里用裸指针，代码更短。

3. **为什么 `present` 要 pitch**
   这是个真 bug 制造机。`Surface` 的每行可能是 644 个像素（后面讲对齐），
   如果你传给 SDL "每行 640 个像素"，SDL 会从第二行开始就错位 4 个像素，
   画面看起来是**斜的**。第 1 阶段的验收会专门测这个。

### 0.5 `src/platform/Window.cpp`

<!-- FILE: src/platform/Window.cpp -->
```cpp
#include "platform/Window.h"
#include "platform/Input.h"      // 滚轮事件要转交给它

#include <SDL.h>
#include <cstdio>
#include <cstdlib>

namespace platform {

struct Window::Impl {
    SDL_Window*   win = nullptr;
    SDL_Renderer* ren = nullptr;
    SDL_Texture*  tex = nullptr;
};

Window::Window(int win_w, int win_h, int internal_w, int internal_h,
               const char* title)
    : iw_(internal_w), ih_(internal_h), ww_(win_w), wh_(win_h)
{
    if (SDL_Init(SDL_INIT_VIDEO) != 0) {
        std::fprintf(stderr, "SDL_Init 失败: %s\n", SDL_GetError());
        std::abort();
    }

    impl_ = new Impl();

    impl_->win = SDL_CreateWindow(
        title,
        SDL_WINDOWPOS_CENTERED, SDL_WINDOWPOS_CENTERED,
        win_w, win_h,
        SDL_WINDOW_SHOWN);
    if (!impl_->win) {
        std::fprintf(stderr, "SDL_CreateWindow 失败: %s\n", SDL_GetError());
        std::abort();
    }

    impl_->ren = SDL_CreateRenderer(
        impl_->win, -1, SDL_RENDERER_ACCELERATED | SDL_RENDERER_PRESENTVSYNC);

    // 没有显卡加速时（远程桌面、虚拟机、SDL_VIDEODRIVER=dummy）退化到软件渲染。
    // 不写这个 fallback 的话，无头自检会直接 abort。
    if (!impl_->ren) {
        impl_->ren = SDL_CreateRenderer(impl_->win, -1, SDL_RENDERER_SOFTWARE);
    }
    if (!impl_->ren) {
        std::fprintf(stderr, "SDL_CreateRenderer 失败: %s\n", SDL_GetError());
        std::abort();
    }

    // 关键：纹理用内部分辨率，不是窗口分辨率
    impl_->tex = SDL_CreateTexture(
        impl_->ren,
        SDL_PIXELFORMAT_ARGB8888,
        SDL_TEXTUREACCESS_STREAMING,
        iw_, ih_);
    if (!impl_->tex) {
        std::fprintf(stderr, "SDL_CreateTexture 失败: %s\n", SDL_GetError());
        std::abort();
    }

    // 关键：最近邻放大，保持像素锐利。默认是线性插值，画面会糊。
    SDL_SetTextureScaleMode(impl_->tex, SDL_ScaleModeNearest);

    // 这里**故意不调用** SDL_RenderSetLogicalSize。
    //
    // 老版本靠它把 640×360 的画面自动铺满窗口，代价是所有绘制坐标都被
    // 隐式乘了 2。ImGui 的后端会读 SDL_RenderGetScale()，一旦发现不是 1
    // 就改用 FramebufferScale，两套缩放叠在一起，UI 会整体偏到屏幕外。
    // 现在改成"自己算目标矩形"：present 时把纹理铺到整个窗口，
    // 坐标系统保持 1:1（1280×720），ImGui 不用猜。
}

Window::~Window() {
    if (impl_) {
        if (impl_->tex) SDL_DestroyTexture(impl_->tex);
        if (impl_->ren) SDL_DestroyRenderer(impl_->ren);
        if (impl_->win) SDL_DestroyWindow(impl_->win);
        delete impl_;
        impl_ = nullptr;
    }
    SDL_Quit();
}

void Window::begin_scene(const uint32_t* pixels, int pitch_pixels) {
    // pitch 是**像素**步长，SDL 要**字节**步长，所以乘 4。
    // SDL_UpdateTexture 的 pitch 参数单位是**字节**
    SDL_UpdateTexture(impl_->tex, nullptr, pixels,
                      pitch_pixels * static_cast<int>(sizeof(uint32_t)));
    SDL_RenderClear(impl_->ren);

    // 铺满窗口。窗口固定 1280×720、画面 640×360，正好 2 倍。
    // 想加"保持宽高比"的黑边，也就改这四行。
    const SDL_Rect dst{ 0, 0, ww_, wh_ };
    SDL_RenderCopy(impl_->ren, impl_->tex, nullptr, &dst);
}

void Window::present() {
    SDL_RenderPresent(impl_->ren);
}

void Window::present(const uint32_t* pixels, int pitch_pixels) {
    begin_scene(pixels, pitch_pixels);
    present();
}

bool Window::read_pixels(uint32_t* dst, int dst_pitch_pixels) const {
    if (!impl_ || !impl_->ren) return false;
    return SDL_RenderReadPixels(impl_->ren, nullptr, SDL_PIXELFORMAT_ARGB8888,
                                dst, dst_pitch_pixels * int(sizeof(uint32_t))) == 0;
}

void* Window::native_window() const {
    return impl_ ? impl_->win : nullptr;
}

void* Window::native_renderer() const {
    return impl_ ? impl_->ren : nullptr;
}

bool Window::poll() {
    SDL_Event e;
    while (SDL_PollEvent(&e)) {
        // UI 先看：ImGui 处理完会告诉我们"这条我用掉了"
        const bool consumed = filter_ ? filter_(&e) : false;

        if (e.type == SDL_QUIT) {
            running_ = false;
        } else if (e.type == SDL_KEYDOWN) {
            // ESC 是"退出游戏"的老快捷键。但用户正在 ImGui 输入框里
            // 按 ESC 取消输入时，这条事件已经被 UI 吃掉了，不能顺手退游戏。
            if (!consumed && e.key.keysym.sym == SDLK_ESCAPE) running_ = false;
        } else if (e.type == SDL_MOUSEWHEEL) {
            // 滚轮没有"查询式"API（SDL_GetMouseState 拿不到它），
            // 只能从事件里拿。所以在这里转交给 Input 累计。
            Input::add_wheel(e.wheel.y);
        }
    }
    return running_;
}

} // namespace platform
```

**逐段解释**：

- `SDL_RENDERER_ACCELERATED | SDL_RENDERER_PRESENTVSYNC`
  `PRESENTVSYNC` 让 `SDL_RenderPresent` 等垂直同步，帧率锁在 60。
  **不加的话主循环会疯跑**，CPU 100%，风扇狂转。开发期想测极限性能可以临时去掉。

- `SDL_CreateTexture(..., iw_, ih_)`
  这里必须用**内部分辨率**。写成 `win_w, win_h` 的话，
  你推上去的 640×360 数据会被当成 1280×720 的一半填进去，画面只有左下角四分之一。

- `SDL_SetTextureScaleMode(..., SDL_ScaleModeNearest)`
  默认是 `Linear`（双线性插值）。640→1280 放大后每个像素变成 2×2 的模糊块，
  像素画就毁了。`Nearest` 才是硬边。

- `SDL_UpdateTexture` 的 pitch
  单位是**字节数**，所以是 `pitch_pixels * 4`。
  这个参数传错的典型症状：画面从第 2 行开始整体右移几个像素，像被斜着剪了一刀。

- `SDL_RenderSetLogicalSize(ren, iw_, ih_)`
  设了之后，`SDL_RenderCopy` 的目标矩形传 `nullptr` 就会自动铺满窗口，
  并按比例缩放。不设的话你得自己算缩放矩形。

### 0.6 `src/main.cpp`（本阶段的临时版）

这一版只是**为了验证窗口能开**，阶段 20 会整个替换掉。
所以这个代码块没有 `FILE` 标记——它不进最终工程。

```cpp
#include "platform/Window.h"
#include <cstdint>
#include <vector>

int main() {
    platform::Window win(1280, 720, 640, 360, "Embers of Eldra - stage 0");

    std::vector<uint32_t> fb(640 * 360);
    while (win.poll()) {
        for (int y = 0; y < 360; ++y) {
            for (int x = 0; x < 640; ++x) {
                const uint32_t r = uint32_t(x * 255 / 639);
                const uint32_t g = uint32_t(y * 255 / 359);
                fb[size_t(y) * 640 + x] = 0xFF000000u | (r << 16) | (g << 8) | 0x40u;
            }
        }
        win.present(fb.data(), 640);
    }
    return 0;
}
```

## 阶段 1 · Surface：自己管的像素缓冲

### 1.1 为什么不用 `SDL_Surface`

`SDL_Surface` 能做这事，但你会失去三样东西：

1. **控制不了 pitch**。SIMD 需要每行 32 字节对齐，`SDL_Surface` 不保证。
2. **控制不了生命周期**。你想让 `Surface` 可移动、不可拷贝，`SDL_Surface` 是 C 结构。
3. **控制不了像素格式**。你得每次检查 `format->BytesPerPixel`。

自己写一个 60 行的类，后面所有代码都干净。这是值得的。

### 1.2 两个必须先想清楚的概念

**pitch（步长）**：一行占多少个像素，**不是 width**。

为什么要大于 width？因为 SIMD 一次读 16 或 32 字节，
如果每行起点不对齐，每次都得用 `loadu`（慢一点），而且跨行读取会踩到别的行。
所以分配时把 width 向上补到 8 的倍数：

```
width = 641  →  pitch = 648   (648 = 8 × 81)
每行末尾多出 7 个像素的填充，内容无所谓
```

**只要用 `row(y)` 取行首，就不会错**。任何时候都别写 `px_ + y * width_`。

**像素格式**：`0xAARRGGBB`，内存里小端存放是 `B,G,R,A`。

```
值:      0xFF   0x40   0x80   0xC0
含义:    alpha  red    green  blue
```

选 ARGB 而不是 RGBA，是因为 SDL 的 `SDL_PIXELFORMAT_ARGB8888` 直接对应，
`SDL_UpdateTexture` 不需要任何转换。

### 1.4 `include/core/Types.h`

<!-- FILE: include/core/Types.h -->
```cpp
#pragma once
#include <cstdint>

namespace core {

struct Vec2i { int x, y; };
struct Vec2f { float x, y; };

// 全项目唯一的矩形定义。
// 不要在任何别的头文件里再写一遍 struct Rect —— 两个不同的 Rect
// 会导致"明明参数对得上却编译不过"，而且报错信息极难看懂。
struct Rect { int x, y, w, h; };

// 像素格式：0xAARRGGBB。小端内存里字节顺序是 B,G,R,A
using Pixel = uint32_t;

constexpr Pixel rgba(uint8_t r, uint8_t g, uint8_t b, uint8_t a = 255) {
    return (Pixel(a) << 24) | (Pixel(r) << 16) | (Pixel(g) << 8) | Pixel(b);
}

constexpr uint8_t alpha_of(Pixel p) { return uint8_t(p >> 24); }
constexpr uint8_t red_of  (Pixel p) { return uint8_t((p >> 16) & 0xFF); }
constexpr uint8_t green_of(Pixel p) { return uint8_t((p >>  8) & 0xFF); }
constexpr uint8_t blue_of (Pixel p) { return uint8_t( p        & 0xFF); }

// 两个矩形是否相交（战斗判定到处在用）
inline bool rect_overlap(Rect a, Rect b) {
    return a.x < b.x + b.w && b.x < a.x + a.w &&
           a.y < b.y + b.h && b.y < a.y + a.h;
}

// 点是否在矩形内
inline bool rect_contains(Rect r, int px, int py) {
    return px >= r.x && py >= r.y && px < r.x + r.w && py < r.y + r.h;
}

} // namespace core
```

> `rect_overlap` 的写法值得看一眼：**不要**写成
> `!(a.x+a.w < b.x || ...)` 那种四重否定，容易漏一个等号。
> 上面这个版本是"a 的左边界在 b 的右边界左边，且 b 的左边界在 a 的右边界左边"，
> 两个方向都满足才算相交。用 `<` 而不是 `<=`，是因为边界相接（刚好贴住）不算相交。

### 1.5 `include/gfx/Surface.h`

<!-- FILE: include/gfx/Surface.h -->
```cpp
#pragma once
#include <cstdint>
#include "core/Types.h"     // Rect / Pixel 的唯一来源

namespace gfx {

using core::Pixel;
using core::Rect;

// 一块自己管理的、32 字节对齐的像素缓冲。
//
// 不可拷贝、可移动。原因：它持有一块 malloc 来的内存，
// 拷贝会变成两个对象指向同一块内存，析构两次 → 崩溃。
class Surface {
public:
    // 默认构造：0×0，不分配内存。
    // 必须有。否则任何"含 Surface 成员"的类（TileMap / Game）都无法默认构造，
    // 报错是 C2280「尝试引用已删除的函数」，看不出跟 Surface 有关。
    Surface() = default;

    Surface(int w, int h);
    ~Surface();

    Surface(const Surface&) = delete;
    Surface& operator=(const Surface&) = delete;
    Surface(Surface&&) noexcept;
    Surface& operator=(Surface&&) noexcept;

    Pixel*       data()       { return px_; }
    const Pixel* data() const { return px_; }

    int width()  const { return w_; }
    int height() const { return h_; }
    int pitch()  const { return pitch_; }   // 每行像素数，≥ width

    // 取第 y 行行首。永远用这个，不要写 px_ + y * w_
    Pixel*       row(int y)       { return px_ + size_t(y) * size_t(pitch_); }
    const Pixel* row(int y) const { return px_ + size_t(y) * size_t(pitch_); }

    void clear(Pixel color);

private:
    void release();

    Pixel* px_ = nullptr;
    int w_ = 0, h_ = 0, pitch_ = 0;
};

} // namespace gfx
```

### 1.6 `src/gfx/Surface.cpp`

<!-- FILE: src/gfx/Surface.cpp -->
```cpp
#include "gfx/Surface.h"

#include <cstdlib>
#include <cstring>
#include <utility>

#ifdef _MSC_VER
#include <malloc.h>     // _aligned_malloc / _aligned_free
#endif

namespace gfx {

// 向上取整到 a 的倍数。a 必须是 2 的幂。
static inline int align_up(int v, int a) { return (v + a - 1) & ~(a - 1); }

Surface::Surface(int w, int h) : w_(w), h_(h) {
    // 每行补到 8 像素 = 32 字节，正好是 AVX2 的对齐要求
    pitch_ = align_up(w, 8);

    const size_t bytes = size_t(pitch_) * size_t(h_) * sizeof(Pixel);

#ifdef _MSC_VER
    px_ = static_cast<Pixel*>(_aligned_malloc(bytes, 32));
#else
    void* p = nullptr;
    if (posix_memalign(&p, 32, bytes) != 0) p = nullptr;
    px_ = static_cast<Pixel*>(p);
#endif

    if (!px_) std::abort();
    std::memset(px_, 0, bytes);
}

Surface::~Surface() { release(); }

void Surface::release() {
    if (!px_) return;
#ifdef _MSC_VER
    _aligned_free(px_);      // 必须配 _aligned_malloc，不能用 free()
#else
    std::free(px_);
#endif
    px_ = nullptr;
}

// 移动：把源对象的指针"偷"过来，并把源置空
Surface::Surface(Surface&& o) noexcept
    : px_(std::exchange(o.px_, nullptr)),
      w_(std::exchange(o.w_, 0)),
      h_(std::exchange(o.h_, 0)),
      pitch_(std::exchange(o.pitch_, 0)) {}

Surface& Surface::operator=(Surface&& o) noexcept {
    if (this != &o) {
        release();                                  // 先放掉自己的
        px_    = std::exchange(o.px_, nullptr);
        w_     = std::exchange(o.w_, 0);
        h_     = std::exchange(o.h_, 0);
        pitch_ = std::exchange(o.pitch_, 0);
    }
    return *this;
}

void Surface::clear(Pixel color) {
    for (int y = 0; y < h_; ++y) {
        Pixel* r = row(y);
        for (int x = 0; x < w_; ++x) r[x] = color;
    }
}

} // namespace gfx
```

**这四段必须理解**：

- `pitch_ = align_up(w, 8)`
  `align_up(641, 8) = 648`。`~(8-1)` 是 `...11111000`，与一下就把低 3 位清零。
  这个写法只对 2 的幂有效。

- `_aligned_malloc` 必须配 `_aligned_free`
  MSVC 的 `_aligned_malloc` 在返回指针**前面**存了原始地址，
  `free()` 会去读那个位置，直接崩。规则：谁分配谁释放，成对出现。

- `std::exchange(o.px_, nullptr)`
  把 `o.px_` 的值给你，同时把 `o.px_` 置空。
  **置空是关键**：不置空的话，`o` 析构时会把这块内存释放掉，
  你手上就是野指针。这是移动语义最经典的错误。

- `operator=` 里的 `if (this != &o)`
  自己移动给自己时，`release()` 会先把自己释放掉，再去读 `o`（就是自己）的指针，拿到 nullptr。
  虽然不出错，但数据没了。加这个判断。

```cpp
    int frame_h = 0;

            return {0, 0, image.width(), image.height()};

        return { (index % cols) * frame_w,
                 (index / cols) * frame_h,
                 frame_w, frame_h };
```

### 2.4 `src/gfx/Atlas.cpp`

<!-- FILE: src/gfx/Atlas.cpp -->
```cpp
#include "gfx/Atlas.h"

#include <SDL_image.h>

#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <filesystem>

namespace gfx {

bool load_png_into(Surface& out, const std::string& path) {
    SDL_Surface* raw = IMG_Load(path.c_str());
    if (!raw) {
        // 热重载路径：读失败是"常态"（文件正被写、刚被删），不是致命错误
        std::fprintf(stderr, "IMG_Load 失败: %s (%s)\n", path.c_str(), IMG_GetError());
        return false;
    }

    // 统一转格式。这一步之后每像素一定是 4 字节、0xAARRGGBB。
    SDL_Surface* conv = SDL_ConvertSurfaceFormat(raw, SDL_PIXELFORMAT_ARGB8888, 0);
    SDL_FreeSurface(raw);
    if (!conv) {
        std::fprintf(stderr, "格式转换失败: %s\n", path.c_str());
        return false;
    }

    Surface tmp(conv->w, conv->h);

    // 逐行拷贝。不能一次 memcpy 整张 —— 两边的 pitch 不一定相等。
    for (int y = 0; y < conv->h; ++y) {
        const uint8_t* src = static_cast<const uint8_t*>(conv->pixels)
                           + size_t(y) * size_t(conv->pitch);
        std::memcpy(tmp.row(y), src, size_t(conv->w) * sizeof(Pixel));
    }

    SDL_FreeSurface(conv);
    out = std::move(tmp);          // 移动赋值，老缓冲自动释放
    return true;
}

Surface load_png(const std::string& path) {
    Surface out;
    if (!load_png_into(out, path)) std::abort();
    return out;
}

std::vector<Surface> load_dir(const std::string& dir) {
    std::vector<Surface> out;
    namespace fs = std::filesystem;

    if (!fs::exists(dir)) {
        std::fprintf(stderr, "目录不存在: %s\n", dir.c_str());
        return out;
    }

    // 递归：objects/ 下面还有子目录（Ores & Ingots、food、weapons...），
    // 不递归的话只能拿到 238 个，递归才是完整的 440 个。
    for (const auto& e : fs::recursive_directory_iterator(dir)) {
        if (!e.is_regular_file()) continue;
        if (e.path().extension() != ".png") continue;
        out.push_back(load_png(e.path().string()));
    }
    return out;
}

} // namespace gfx
```

**为什么必须逐行拷**：

```
SDL 那边:   [========w*4========][padding]   每行 stride = conv->pitch
你这边:     [========w*4========][padding]   每行 stride = out.pitch()
```

两个 padding 长度不同，一次 `memcpy(w*h*4)` 从第二行开始就错位。
正确做法是按行拷 `w*4` 字节，各用各的 stride。

## 阶段 3 · Blitter：带裁剪的 alpha 混合

### 3.1 alpha 混合的数学

```
dst = src * a + dst * (1 - a)        a ∈ [0, 1]
```

用 0–255 的整数表示，`a` 是源的 alpha，`inv = 255 - a`：

```
dst = (src * a + dst * inv) / 255
```

**注意 `/255` 是向零取整（floor）**。这一点后面写 SIMD 时会变成关键：
SIMD 的 `div255` 实现是**四舍五入**，两者差 1。
所以黄金测试必须允许 ±1，或者两边都用同一个 `div255`。

两个快速路径必须先判断，否则性能砍半：

- `a == 0` → 什么都不做（大量精灵的空白区域）
- `a == 255` → 直接 `dst = src`（不透明区域，占大多数）

### 3.2 为什么先写标量版

因为标量版是**黄金标准**。SIMD 版对不对，靠它来判断。
先写标量、跑通、再优化——顺序反了，你永远不知道是算法错还是 SIMD 写错。

```cpp
#include "gfx/Blitter.h"
#include "simd/Backend.h"

#include <cstring>

namespace gfx {

void blend_pixel_scalar(Pixel& d, Pixel s) {
    const uint32_t a = s >> 24;
    if (a == 0)   return;              // 全透明：跳过
    if (a == 255) { d = s; return; }   // 全不透明：直接覆盖

    const uint32_t inv = 255 - a;
    const uint32_t sr = (s >> 16) & 0xFF, sg = (s >> 8) & 0xFF, sb = s & 0xFF;
    const uint32_t dr = (d >> 16) & 0xFF, dg = (d >> 8) & 0xFF, db = d & 0xFF;

    d = 0xFF000000u
      | (((sr * a + dr * inv) / 255) << 16)
      | (((sg * a + dg * inv) / 255) << 8)
      |  ((sb * a + db * inv) / 255);
}

// 裁剪。返回 false 表示完全在屏幕外。
//
// 顺序不能反：先裁源矩形，再裁目标偏移。
// 反了会得到负的宽高，后面的循环一次都不执行，症状是"精灵消失了"。
static bool clip(Surface& dst, const Surface& src, Rect& r, int& dx, int& dy,
                 int& sx, int& sy, int& w, int& h) {
    // 1) 源矩形不能超出源图
    if (r.x < 0) { dx -= r.x; r.w += r.x; r.x = 0; }
    if (r.y < 0) { dy -= r.y; r.h += r.y; r.y = 0; }
    if (r.x + r.w > src.width())  r.w = src.width()  - r.x;
    if (r.y + r.h > src.height()) r.h = src.height() - r.y;

    sx = r.x; sy = r.y; w = r.w; h = r.h;

    // 2) 目标位置不能超出屏幕
    if (dx < 0) { sx -= dx; w += dx; dx = 0; }
    if (dy < 0) { sy -= dy; h += dy; dy = 0; }
    if (dx + w > dst.width())  w = dst.width()  - dx;
    if (dy + h > dst.height()) h = dst.height() - dy;

    return w > 0 && h > 0;
}

void blit_alpha(Surface& dst, const Surface& src, Rect r, int dx, int dy) {
    int sx, sy, w, h;
    if (!clip(dst, src, r, dx, dy, sx, sy, w, h)) return;

    for (int y = 0; y < h; ++y) {
        const Pixel* s = src.row(sy + y) + sx;
        Pixel*       d = dst.row(dy + y) + dx;
        simd::blend_row(d, s, w);          // ← 阶段 4 换的就是这一行
    }
}

void blit_opaque(Surface& dst, const Surface& src, Rect r, int dx, int dy) {
    int sx, sy, w, h;
    if (!clip(dst, src, r, dx, dy, sx, sy, w, h)) return;

    for (int y = 0; y < h; ++y) {
        std::memcpy(dst.row(dy + y) + dx, src.row(sy + y) + sx,
                    size_t(w) * sizeof(Pixel));
    }
}

void blit_tinted(Surface& dst, const Surface& src, Rect r, int dx, int dy, Pixel tint) {
    int sx, sy, w, h;
    if (!clip(dst, src, r, dx, dy, sx, sy, w, h)) return;

    const uint32_t tr = (tint >> 16) & 0xFF;
    const uint32_t tg = (tint >> 8) & 0xFF;
    const uint32_t tb = tint & 0xFF;

    for (int y = 0; y < h; ++y) {
        const Pixel* s = src.row(sy + y) + sx;
        Pixel*       d = dst.row(dy + y) + dx;
        for (int x = 0; x < w; ++x) {
            const Pixel p = s[x];
            const uint32_t a = p >> 24;
            if (a == 0) continue;
            const uint32_t rr = (((p >> 16) & 0xFF) * tr) / 255;
            const uint32_t gg = (((p >> 8) & 0xFF) * tg) / 255;
            const uint32_t bb = ((p & 0xFF) * tb) / 255;
            blend_pixel_scalar(d[x], (a << 24) | (rr << 16) | (gg << 8) | bb);
        }
    }
}

void blit_mask(Surface& dst, const Surface& src, Rect r, int dx, int dy, Pixel color) {
    int sx, sy, w, h;
    if (!clip(dst, src, r, dx, dy, sx, sy, w, h)) return;

    const Pixel rgb = color & 0x00FFFFFFu;
    for (int y = 0; y < h; ++y) {
        const Pixel* srow = src.row(sy + y);
        Pixel*       drow = dst.row(dy + y);
        for (int x = 0; x < w; ++x) {
            const uint8_t a = core::alpha_of(srow[sx + x]);
            if (!a) continue;                       // 全透明的像素跳过
            blend_pixel_scalar(drow[dx + x], (Pixel(a) << 24) | rgb);
        }
    }
}

void fill_rect(Surface& dst, Rect r, Pixel color) {
    const int x0 = r.x < 0 ? 0 : r.x;
    const int y0 = r.y < 0 ? 0 : r.y;
    const int x1 = r.x + r.w > dst.width()  ? dst.width()  : r.x + r.w;
    const int y1 = r.y + r.h > dst.height() ? dst.height() : r.y + r.h;

    for (int y = y0; y < y1; ++y) {
        Pixel* d = dst.row(y);
        for (int x = x0; x < x1; ++x) d[x] = color;
    }
}

void fill_rect_alpha(Surface& dst, Rect r, Pixel color) {
    const int a = int(core::alpha_of(color));
    if (a == 0) return;                        // 全透明：什么也不做
    if (a == 255) { fill_rect(dst, r, color); return; }

    const int x0 = r.x < 0 ? 0 : r.x;
    const int y0 = r.y < 0 ? 0 : r.y;
    const int x1 = r.x + r.w > dst.width()  ? dst.width()  : r.x + r.w;
    const int y1 = r.y + r.h > dst.height() ? dst.height() : r.y + r.h;
    if (x0 >= x1 || y0 >= y1) return;

    for (int y = y0; y < y1; ++y) {
        Pixel* d = dst.row(y);
        for (int x = x0; x < x1; ++x) blend_pixel_scalar(d[x], color);
    }
}

void blit_stretch(Surface& dst, const Surface& src, Rect s, Rect d) {
    if (d.w <= 0 || d.h <= 0 || s.w <= 0 || s.h <= 0) return;

    for (int y = 0; y < d.h; ++y) {
        const int dy = d.y + y;
        if (dy < 0 || dy >= dst.height()) continue;      // 纵向裁剪，漏了会段错误

        const int sy = s.y + y * s.h / d.h;              // 最近邻采样
        if (sy < 0 || sy >= src.height()) continue;

        const Pixel* srow = src.row(sy);
        Pixel*       drow = dst.row(dy);
        for (int x = 0; x < d.w; ++x) {
            const int dx = d.x + x;
            if (dx < 0 || dx >= dst.width()) continue;   // 横向裁剪
            const int sx = s.x + x * s.w / d.w;
            if (sx < 0 || sx >= src.width()) continue;
            blend_pixel_scalar(drow[dx], srow[sx]);
        }
    }
}

} // namespace gfx
```

### 3.6 裁剪：为什么顺序不能反

假设你要把一个 64×64 的精灵画在 `(-32, -10)`（一半在屏幕外）：

```
第一步：裁源
  源矩形  (0,0,64,64)  →  (32,10,32,54)
  目标偏移 (-32,-10)   →  (0,0)
  含义：从源的第 32 列、第 10 行开始取，画到屏幕左上角

第二步：裁目标
  屏幕上只剩 32×54 的空间，再按屏幕边界收一次
```

如果先裁目标：`dx=-32` 先把 `w` 变成 `64 + (-32) = 32`，
但 `sx` 还是 0，于是你从源的第 0 列开始取——**取错了位置**，
精灵看起来"往右跳了一下"。

### 3.7 一个必须知道的性能事实

`blit_alpha` 的时间大部分花在**读显存/内存**上，不是算术上。
一个 64×64 的精灵 = 4096 像素 = 16KB 源 + 16KB 目标。
现代 CPU 一次能算 8 个像素，但内存一次只能搬那么多。

所以：

- **SIMD 在 `blit_alpha` 上提升有限**（通常 1.5–2 倍，不是 8 倍）。
- 真正的加速来自**跳过**：`a == 0` 的像素根本不读目标。
  对角色精灵来说，透明像素常占 50% 以上。
- 第二个战场是**全屏 tint**（每帧处理 23 万像素），那里 SIMD 接近线性加速。

```cpp
void blend_row_avx2  (gfx::Pixel* d, const gfx::Pixel* s, int n);

inline void blend_row(gfx::Pixel* d, const gfx::Pixel* s, int n) {
    switch (active()) {
        case Isa::AVX2: return blend_row_avx2(d, s, n);
        case Isa::SSE2: return blend_row_sse2(d, s, n);
        default:        return blend_row_scalar(d, s, n);

}
```

### 4.5 `src/simd/Kernels.cpp`（标量 + SSE2）

<!-- FILE: src/simd/Kernels.cpp -->
```cpp
#include "simd/Backend.h"

#include <immintrin.h>
#include <cstdint>

namespace simd {

// ---------------------------------------------------------------
// 1) 标量：黄金标准。SIMD 版对不对，靠它判断。
// ---------------------------------------------------------------
void blend_row_scalar(gfx::Pixel* dst, const gfx::Pixel* src, int n) {
    for (int i = 0; i < n; ++i) {
        const gfx::Pixel s = src[i];
        gfx::Pixel& d = dst[i];

        const uint32_t a = s >> 24;
        if (a == 0) continue;
        if (a == 255) { d = s; continue; }

        const uint32_t inv = 255 - a;
        const uint32_t sr = (s >> 16) & 0xFF, sg = (s >> 8) & 0xFF, sb = s & 0xFF;
        const uint32_t dr = (d >> 16) & 0xFF, dg = (d >> 8) & 0xFF, db = d & 0xFF;

        d = 0xFF000000u
          | (((sr * a + dr * inv) / 255) << 16)
          | (((sg * a + dg * inv) / 255) << 8)
          |  ((sb * a + db * inv) / 255);
    }
}

// ---------------------------------------------------------------
// 2) div255：把 x/255 算成 round(x/255)
//
//    (x + 128)
//    ---------  ≈  ((x + 128) + ((x + 128) >> 8)) >> 8
//       255
//
//    第一步加 128 = 四舍五入；后两步是 "除以 255 用除以 256 逼近"。
//    误差：对 x ∈ [0, 65025] 最大偏差 1，且偏的方向固定（比 floor 大 1）。
//
//    这就是黄金测试必须容忍 ±1 的原因。
// ---------------------------------------------------------------
static inline __m128i div255_epi16(__m128i x) {
    const __m128i k128 = _mm_set1_epi16(128);
    const __m128i t = _mm_add_epi16(x, k128);
    const __m128i u = _mm_srli_epi16(t, 8);
    return _mm_srli_epi16(_mm_add_epi16(t, u), 8);
}

// 一次处理 4 个像素（16 字节）
static inline __m128i blend4_core(__m128i s, __m128i d) {
    const __m128i zero = _mm_setzero_si128();

    // 8 位 → 16 位，否则乘法会溢出。
    // 低 8 字节（前 2 个像素）和高 8 字节（后 2 个像素）分开处理。
    __m128i s_lo = _mm_unpacklo_epi8(s, zero);   // [B0 G0 R0 A0 | B1 G1 R1 A1]
    __m128i s_hi = _mm_unpackhi_epi8(s, zero);   // [B2 G2 R2 A2 | B3 G3 R3 A3]
    __m128i d_lo = _mm_unpacklo_epi8(d, zero);
    __m128i d_hi = _mm_unpackhi_epi8(d, zero);

    // 把每个像素的 A 广播到该像素的 4 个通道。
    // 0xFF 是"复制第 3 个 word 到全部 4 个 word"，lo/hi 各一次覆盖 4 个 word。
    __m128i a_lo = _mm_shufflehi_epi16(_mm_shufflelo_epi16(s_lo, 0xFF), 0xFF);
    __m128i a_hi = _mm_shufflehi_epi16(_mm_shufflelo_epi16(s_hi, 0xFF), 0xFF);

    const __m128i k255 = _mm_set1_epi16(255);

    // 关键：先除再加。
    // s*a 最大 255*255 = 65025，d*inv 也是 65025，
    // 直接相加 130050 会溢出 16 位（上限 65535）。
    // 分开除之后每个 ≤255，加起来 ≤510，安全。
    __m128i r_lo = _mm_add_epi16(
        div255_epi16(_mm_mullo_epi16(s_lo, a_lo)),
        div255_epi16(_mm_mullo_epi16(d_lo, _mm_sub_epi16(k255, a_lo))));

    __m128i r_hi = _mm_add_epi16(
        div255_epi16(_mm_mullo_epi16(s_hi, a_hi)),
        div255_epi16(_mm_mullo_epi16(d_hi, _mm_sub_epi16(k255, a_hi))));

    // 16 位 → 8 位（带饱和，>255 截成 255，负数截成 0）
    __m128i out = _mm_packus_epi16(r_lo, r_hi);

    // 强制不透明。alpha 已经在混合里用掉了，输出不需要它。
    return _mm_or_si128(out, _mm_set1_epi32(0xFF000000u));
}

void blend_row_sse2(gfx::Pixel* dst, const gfx::Pixel* src, int n) {
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        __m128i s = _mm_loadu_si128(reinterpret_cast<const __m128i*>(src + i));
        __m128i d = _mm_loadu_si128(reinterpret_cast<const __m128i*>(dst + i));
        _mm_storeu_si128(reinterpret_cast<__m128i*>(dst + i), blend4_core(s, d));
    }
    // 尾部 0–3 个像素交给标量
    for (; i < n; ++i) {
        const gfx::Pixel s = src[i];
        gfx::Pixel& d = dst[i];
        const uint32_t a = s >> 24;
        if (a == 0) continue;
        if (a == 255) { d = s; continue; }
        const uint32_t inv = 255 - a;
        const uint32_t sr = (s >> 16) & 0xFF, sg = (s >> 8) & 0xFF, sb = s & 0xFF;
        const uint32_t dr = (d >> 16) & 0xFF, dg = (d >> 8) & 0xFF, db = d & 0xFF;
        d = 0xFF000000u
          | (((sr * a + dr * inv) / 255) << 16)
          | (((sg * a + dg * inv) / 255) << 8)
          |  ((sb * a + db * inv) / 255);
    }
}

} // namespace simd
```

**`_mm_loadu_si128` 的 `u` 是 unaligned**。
理论上每行已经 32 字节对齐，能用 `_mm_load_si128`（更快一丁点）。
但 `blit_alpha` 经常从一行中间开始（裁剪后 `sx` 不是 8 的倍数），
用对齐版本会直接崩。**统一用 `loadu`，别赌**。

### 4.6 `src/simd/KernelsAVX2.cpp`（AVX2）

<!-- FILE: src/simd/KernelsAVX2.cpp -->
```cpp
// 这个文件必须单独开 /arch:AVX2（-mavx2），见 CMakeLists。
// 其他文件不能开，否则程序在没 AVX2 的机器上起不来。
#include "simd/Backend.h"

#include <immintrin.h>

namespace simd {

// 和 SSE2 版内核相同。这里重新写一份，是为了让这个翻译单元
// 不依赖 Kernels.cpp 里的 static inline 函数（跨 TU 内联不了）。
static inline __m128i blend4_core_avx(__m128i s, __m128i d) {
    const __m128i zero = _mm_setzero_si128();

    __m128i s_lo = _mm_unpacklo_epi8(s, zero);
    __m128i s_hi = _mm_unpackhi_epi8(s, zero);
    __m128i d_lo = _mm_unpacklo_epi8(d, zero);
    __m128i d_hi = _mm_unpackhi_epi8(d, zero);

    __m128i a_lo = _mm_shufflehi_epi16(_mm_shufflelo_epi16(s_lo, 0xFF), 0xFF);
    __m128i a_hi = _mm_shufflehi_epi16(_mm_shufflelo_epi16(s_hi, 0xFF), 0xFF);

    const __m128i k255 = _mm_set1_epi16(255);
    const __m128i k128 = _mm_set1_epi16(128);

    auto div255 = [k128](__m128i x) {
        const __m128i t = _mm_add_epi16(x, k128);
        const __m128i u = _mm_srli_epi16(t, 8);
        return _mm_srli_epi16(_mm_add_epi16(t, u), 8);
    };

    __m128i r_lo = _mm_add_epi16(
        div255(_mm_mullo_epi16(s_lo, a_lo)),
        div255(_mm_mullo_epi16(d_lo, _mm_sub_epi16(k255, a_lo))));
    __m128i r_hi = _mm_add_epi16(
        div255(_mm_mullo_epi16(s_hi, a_hi)),
        div255(_mm_mullo_epi16(d_hi, _mm_sub_epi16(k255, a_hi))));

    __m128i out = _mm_packus_epi16(r_lo, r_hi);
    return _mm_or_si128(out, _mm_set1_epi32(0xFF000000u));
}

// 一次 8 个像素。
//
// 注意：这里**没有**用到 256 位整数运算，是"两个 128 位半区各跑一遍"。
// 原因见下面注释——AVX2 的 unpack/pack 是按 128 位半区独立工作的，
// 直接写 256 位版本会把像素顺序搞乱。
void blend_row_avx2(gfx::Pixel* dst, const gfx::Pixel* src, int n) {
    int i = 0;
    for (; i + 8 <= n; i += 8) {
        __m128i s0 = _mm_loadu_si128(reinterpret_cast<const __m128i*>(src + i + 0));
        __m128i d0 = _mm_loadu_si128(reinterpret_cast<const __m128i*>(dst + i + 0));
        __m128i s1 = _mm_loadu_si128(reinterpret_cast<const __m128i*>(src + i + 4));
        __m128i d1 = _mm_loadu_si128(reinterpret_cast<const __m128i*>(dst + i + 4));

        _mm_storeu_si128(reinterpret_cast<__m128i*>(dst + i + 0), blend4_core_avx(s0, d0));
        _mm_storeu_si128(reinterpret_cast<__m128i*>(dst + i + 4), blend4_core_avx(s1, d1));
    }
    // 尾部（n%8 个像素）
    blend_row_scalar(dst + i, src + i, n - i);
}

} // namespace simd
```

**为什么不用真正的 256 位**：

`_mm256_unpacklo_epi8` 和 `_mm256_packus_epi16` 是**按两个 128 位半区各自独立**工作的。
你以为 `unpacklo` 拿到 `[p0 p1 p2 p3]`，实际拿到 `[p0 p1 | p4 p5]`。
后续 `packus` 再把顺序打乱一次，结果是 **8 个像素里有 4 个位置错乱**。
我实测过：`FF070F17 ...` 变成 `FF081018 ...`，第 3、5 个像素跳位了。

正确写法要么用 `_mm256_permute4x64_epi64` 重排（但 unpack 已经乱过，救不回来），
要么就像上面这样**拆成两个半区**。后者简单、正确、性能几乎一样
（瓶颈在内存，不在位宽）。

### 4.7 `src/simd/Backend.cpp`（CPU 探测）

<!-- FILE: src/simd/Backend.cpp -->
```cpp
#include "simd/Backend.h"

#include <intrin.h>

namespace simd {

namespace {

struct CpuInfo {
    bool sse2  = false;
    bool sse41 = false;
    bool avx2  = false;
};

CpuInfo probe_cpu() {
    CpuInfo info;
    int regs[4];

    __cpuid(regs, 0);
    const int max_id = regs[0];
    if (max_id < 1) return info;

    // CPUID leaf 1: EDX bit 26 = SSE2, ECX bit 19 = SSE4.1
    __cpuid(regs, 1);
    info.sse2  = (regs[3] & (1 << 26)) != 0;
    info.sse41 = (regs[2] & (1 << 19)) != 0;

    if (max_id >= 7) {
        // leaf 7 subleaf 0: EBX bit 5 = AVX2
        __cpuidex(regs, 7, 0);
        info.avx2 = (regs[1] & (1 << 5)) != 0;

        // 关键：光有 CPU 支持不够，操作系统必须已经打开 YMM 寄存器保存。
        // XCR0 的 bit1(SSE) 和 bit2(AVX) 都为 1 才行，否则 AVX 指令会崩。
        const unsigned long long xcr0 = _xgetbv(0);
        if ((xcr0 & 0x6) != 0x6) info.avx2 = false;
    }
    return info;
}

} // namespace

Isa detect() {
    // static 局部变量：只在第一次调用时执行，之后直接返回缓存值。
    // C++11 起这是线程安全的，不需要加锁。
    static const Isa isa = [] {
        const CpuInfo c = probe_cpu();
        if (c.avx2) return Isa::AVX2;
        if (c.sse2) return Isa::SSE2;
        return Isa::Scalar;
    }();
    return isa;
}

Isa active() { return detect(); }

const char* isa_name(Isa i) {
    switch (i) {
        case Isa::AVX2: return "AVX2";
        case Isa::SSE2: return "SSE2";
        default:        return "scalar";
    }
}

} // namespace simd
```

**`_xgetbv(0)` 那一行不能省**。有 CPU 支持 AVX2 但操作系统没开 YMM 保存的情况
（老 Windows 7 没装 SP1、某些虚拟机），此时执行 AVX2 指令会直接崩。

### 4.8 验收：黄金测试

这个测试比"看着像不像"可靠一万倍。**每次改 kernel 都跑一遍**。

```cpp
#include "simd/Backend.h"
#include <cstdio>
#include <cstdlib>     // std::abs(int)
#include <random>
#include <vector>

int main() {
    std::printf("检测到后端: %s\n", simd::isa_name(simd::active()));

    const int N = 1024;
    std::vector<gfx::Pixel> src(N), dst0(N), dst1(N), dst2(N);
    std::mt19937 rng(12345);
    for (int i = 0; i < N; ++i) {
        src[i]  = (uint32_t(rng() % 256) << 24) | (rng() & 0xFFFFFF);
        dst0[i] = 0xFF000000u | (rng() & 0xFFFFFF);
    }
    dst1 = dst0;
    dst2 = dst0;

    simd::blend_row_scalar(dst0.data(), src.data(), N);
    simd::blend_row_sse2  (dst1.data(), src.data(), N);
    simd::blend_row_avx2  (dst2.data(), src.data(), N);

    auto cmp = [&](const char* name, const std::vector<gfx::Pixel>& a) {
        int bad = 0, maxdiff = 0;
        for (int i = 0; i < N; ++i) {
            for (int sh = 0; sh < 24; sh += 8) {
                const int d = std::abs(int((a[i] >> sh) & 0xFF) - int((dst0[i] >> sh) & 0xFF));
                if (d > 0) { ++bad; if (d > maxdiff) maxdiff = d; }
            }
        }
        std::printf("%-8s 不一致 %4d 处，最大差 %d  %s\n",
                    name, bad, maxdiff, maxdiff <= 1 ? "(通过)" : "(失败)");
    };
    cmp("SSE2", dst1);
    cmp("AVX2", dst2);
    return 0;
}
```

- [ ] 打印出后端名（这台机器应该是 `AVX2`）
- [ ] SSE2 / AVX2 都是"最大差 1（通过）"
- [ ] **最大差是 1 不是 0，这是对的**——`div255` 四舍五入，标量版是 floor
- [ ] 把 `N` 改成 1021（不是 8 的倍数），仍然通过（测尾部处理）
