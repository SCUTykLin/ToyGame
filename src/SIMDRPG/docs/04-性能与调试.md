# 04 · 性能与调试

> 这一章的目的只有一个：**让你能证明"我优化了"是真的，而不是感觉。**
> 上次评审里说的"零测试"，这里就是补课。

---

## 1. 先学会正确地测

### 1.1 错误示范（90% 的人都这么写）

```cpp
auto t0 = clock();
blit_alpha(fb, a, r, 0, 0);
auto t1 = clock();
printf("%f ms\n", double(t1 - t0) / CLOCKS_PER_SEC * 1000);
```

**四个致命问题**：

| 问题 | 后果 |
|------|------|
| 只跑一次 | 受 CPU 频率、缓存冷热影响，误差可能 10 倍 |
| `clock()` 返回的是 CPU 时间，且精度只有毫秒级 | 测不出 GPU 等待、系统调度，多线程下更不准 |
| 结果没被使用 | 编译器可能**整个优化掉**（尤其 inline 后） |
| 第一次跑 | 数据和代码都不在缓存里，必然慢 |

### 1.2 正确写法

```cpp
#include <chrono>
#include <algorithm>
#include <vector>

template <typename Fn>
double bench_ms(Fn&& fn, int warmup = 20, int iters = 200) {
    for (int i = 0; i < warmup; ++i) fn();          // 预热缓存

    std::vector<double> samples;
    samples.reserve(iters);
    for (int i = 0; i < iters; ++i) {
        auto t0 = std::chrono::steady_clock::now();
        fn();
        auto t1 = std::chrono::steady_clock::now();
        samples.push_back(std::chrono::duration<double, std::milli>(t1 - t0).count());
    }
    std::sort(samples.begin(), samples.end());
    return samples[samples.size() / 2];             // 取中位数，别取平均
}
```

**为什么取中位数**：偶尔一次被系统调度打断，平均值会被拉高，中位数不受影响。

**为什么 warmup**：第一次调用时，指令缓存、数据缓存、分支预测器全是冷的。

### 1.3 防止被优化掉

```cpp
volatile uint32_t sink;      // 全局

void bench_blend() {
    // ...
    sink = dst[0];           // 把结果"用"掉，编译器就不敢删
}
```

或者更干净：把结果写到 `std::atomic_signal_fence` 之外的全局数组。

## 2. 测什么：三个必测项

```cpp
// 准备：一张 64x64 的半透明精灵，铺满一行
std::vector<uint32_t> src(1280), dst(1280);
// 填成 alpha = 128 的半透明
for (auto& p : src) p = 0x80FF8040u;

double scalar = bench_ms([&]{ for(int i=0;i<w;++i) blend_pixel_scalar(dst[i], src[i]); });
double simd   = bench_ms([&]{ simd::blend_row_sse2(dst.data(), src.data(), w); });

printf("标量 %.3f ms | SIMD %.3f ms | 加速 %.2fx\n", scalar, simd, scalar/simd);
```

| 必测项 | 为什么 |
|--------|--------|
| 全不透明（alpha=255） | 标量有快速路径，SIMD 优势最小 —— 这是**最坏情况** |
| 全半透明（alpha=128） | SIMD 主战场 |
| 真实精灵（80% 不透明 + 20% 边缘） | 才是你游戏里的实际情况 |

**必须把三种都测**，否则你会得出错误结论。

## 3. 如果 SIMD 没快多少，按这个顺序查

### 检查 1：你跑的是哪条路径？

```cpp
printf("后端 = %s\n", isa_name(simd::active()));
```

如果打印 `scalar`，后面全白测。

### 检查 2：Release 还是 Debug？

Debug 下 intrinsics **不会被内联**，每次 `_mm_add_epi16` 都是一次函数调用。
性能可能比标量还差。

```cmake
cmake -B build -DCMAKE_BUILD_TYPE=Release
```

### 检查 3：数据在缓存里吗？

1280 像素 = 5KB，L1 缓存能装下。如果测的是整屏 921600 像素（3.7MB），
会跑在 L3 甚至内存上，**这时候瓶颈是带宽不是计算**，SIMD 优势会被稀释。

> 这是真实情况：大规模像素处理是**内存带宽受限**的。
> 所以 SIMD 的收益在"数据能进 L2"的规模下最明显。

### 检查 4：标量版是不是有快速路径？

如果你的测试数据里 80% 是 `alpha == 255`，标量版一个 `if` 就跳过了，
SIMD 却老老实实算了 8 个 —— 这时候 **SIMD 反而更慢是正常的**。

**这不是 bug**，是场景选择问题。解法：

```cpp
void blit_alpha(Surface& dst, const Surface& src, Rect r, int dx, int dy) {
    for (int y = 0; y < h; ++y) {
        // 先扫一遍这一行有没有非不透明像素
        bool any_alpha = false;
        for (int x = 0; x < w; ++x)
            if ((s[x] >> 24) != 0xFF) { any_alpha = true; break; }

        if (!any_alpha) {
            std::memcpy(d + dx, s, w * sizeof(Pixel));   // 整行直接拷
        } else {
            simd::blend_row(d + dx, s, w);
        }
    }
}
```

这个「行级快速跳过」通常比任何 SIMD 优化都有效，**因为它直接不干活**。

### 检查 5：看汇编

```bash
# MSVC
dumpbin /disasm build/simdrpg.dir/Release/KernelsAVX2.cpp.obj

# GCC/Clang
objdump -d --no-show-raw-insn build/CMakeFiles/simdrpg.dir/src/simd/KernelsAVX2.cpp.o
```

找 `paddw` / `pmullw` / `packuswb` 这些指令。
如果看到大量 `call`，说明没内联（通常是 Debug 或没开优化）。

## 4. 性能预算（60 FPS = 每帧 16.6ms）

| 项目 | 预算 | 说明 |
|------|------|------|
| 地图渲染（可见 40×23 tiles = 920 个） | 3.0 ms | 每个 tile 一次 `blit_opaque` |
| 实体渲染（30 个精灵） | 1.5 ms | 主要在 alpha 混合 |
| 天气粒子更新（4096 个） | 0.3 ms | SIMD |
| 天气后处理（全屏 tint） | 1.0 ms | 全屏 92 万像素 |
| 逻辑（AI、碰撞） | 1.0 ms | |
| 上屏（`SDL_UpdateTexture`） | 2.0 ms | 受内存带宽限制 |
| **合计** | **8.8 ms** | 还剩 7.8ms 余量 |

**如果你超了，先看最大的那项**，别去优化 0.1ms 的东西。

### 优化顺序（从性价比高到低）

1. **不画**（视锥裁剪、行级跳过）
2. **少画**（降低粒子数、缩小后处理区域）
3. **批量画**（把多次小 blit 合成一次大 blit）
4. **SIMD 加速**（本章）
5. **多线程**（最后考虑，调试成本高）

> 这个顺序很重要。我见过有人为了省 0.2ms 手写 AVX-512，
> 却没想到把可视区外的 800 个 tile 也画了 —— 那能省 3ms。

## 5. 画面错乱的排查流程

这是**你一定会遇到**的问题。按这个顺序查：

### 症状：整块画面斜着错位

```
原因：pitch 计算错，或者行偏移用了 w * y
验证：把 Surface 的 w 改成 65（奇数）再跑
```

### 症状：精灵边缘有黑色描边

```
原因：alpha 通道被当成颜色参与了运算，或者 pack 时没强制 alpha=255
验证：画一个 50% alpha 的纯红方块，看边缘是不是变暗
```

### 症状：AVX2 下出现左右交错条纹

```
原因：packus 之后少了 permute4x64
验证：只画 8 个像素，逐字节 dump 内存对照
```

### 症状：右下角最后几列是花的

```
原因：尾部循环漏了，或者循环条件是 i < n 而不是 i + 8 <= n
验证：把 n 设为 9（8 + 1）跑
```

### 症状：偶发崩溃，崩在 movdqa

```
原因：对齐假设被破坏
验证：打印 ((uintptr_t)ptr) % 32，必须为 0
```

### 症状：MSVC 下满屏"语法错误"，但代码明明是对的 ⚠️

```
error C2059: 语法错误: ')'
error C2143: 语法错误: 缺少 ';'
```

**如果你的源码里有中文（注释或字符串），文件又是 UTF-8 无 BOM，这就是原因。**

MSVC 默认按系统代码页（中文 Windows 是 GBK/936）解析源文件。
UTF-8 的中文在 GBK 下会被解释成乱七八糟的字节，
正好把某个字符串或注释"撑破"，导致莫名其妙的语法错误——
**而且报错位置通常在出错行的下面几十行**，极难定位。

三种解法，任选：

1. **加 `/utf-8` 编译选项**（推荐，本项目的 `CMakeLists.txt` 已加）
   ```cmake
   add_compile_options(/utf-8)
   ```
2. 给源文件**加 BOM**（`文件 -> 另存为 -> UTF-8 with BOM`）
3. 源码里**不写中文**（英文注释 + 英文字符串）

> 我在写这份讲义的验证程序时真的踩了这个坑：
> 一个 250 行的 `verify_simd.cpp`，报错在第 235 行的 `}`，
> 实际原因却是第 1 行的中文注释。加了 `/utf-8` 立刻通过。
>
> GCC/Clang 默认就是 UTF-8，所以这个坑只在 MSVC 上出现。

### 通用手段：把中间结果 dump 出来

```cpp
void dump4(const char* tag, __m128i v) {
    alignas(16) uint32_t out[4];
    _mm_store_si128(reinterpret_cast<__m128i*>(out), v);
    printf("%s: %08X %08X %08X %08X\n", tag, out[0], out[1], out[2], out[3]);
}
```

在每个中间步骤插一行，和标量版逐步对照 —— **这是最快找到错位点的方法**。

## 6. 帧率统计

```cpp
struct FrameStats {
    std::array<double, 120> history{};
    int idx = 0;

    void push(double ms) { history[idx++ % history.size()] = ms; }

    double avg() const {
        double s = 0;
        for (double v : history) s += v;
        return s / history.size();
    }
    double worst() const {
        return *std::max_element(history.begin(), history.end());
    }
};
```

显示在屏幕角落：`avg 6.2ms / worst 11.4ms / 60fps`

**`worst` 比 `avg` 重要**：玩家感受到的卡顿是 worst 造成的。
如果 worst 是 avg 的 3 倍，说明有个偶发的重活（比如新地图加载）。

## 7. 常见"优化"骗局

| 你以为 | 实际 |
|--------|------|
| 加了 `-O3` 就快 | 可能比 `-O2` 慢（代码膨胀，缓存失效） |
| 用了 AVX2 就比 SSE2 快一倍 | 受内存带宽限制，通常只快 20~40% |
| 多线程一定快 | 4 线程画像素，同步开销可能吃掉全部收益 |
| 减少函数调用能提速 | 编译器早就内联了 |
| `float` 比 `int` 快 | 现代 CPU 上整数 SIMD 往往更快（没有浮点转换） |
