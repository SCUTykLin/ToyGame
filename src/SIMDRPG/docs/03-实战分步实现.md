## 两条路线

### 主线（默认）：自顶向下

```
1. 从这里开始「一、现在就做」           建 main + Game 骨架（此时编译不过是对的）
2. 从这里开始「二、动手前先看清整体」   一帧调用链、九个模块、三种联系、所有权
3. 从这里开始「三、卡到哪，补到哪」     写到哪缺什么 → 去哪一册抄 → 补完能看到什么
4. 每下沉一层就编译一次          完整文件从 03a–03g 整块粘，桩不要留到最后
5. 01 / 02 / 03f / 04           按需查：分层契约、SIMD 推导、编译顺序、性能
```

`从这里开始` 末尾附录列了这条路的代价（接口返工、桩的进度幻觉、底层知识被打断等），不想看可以跳过。

### 备选：按依赖顺序（旧路线）

```
1. 00 → 01                      背景 + 分层
2. 02                          在阶段 4 之前读一遍
3. 03a → 03b → 03c → 03d → 03e → 03g
4. 卡住了查 03f
```

这条路编译最顺、返工最少，适合只想完整抄出一个能跑的工程；
缺点是前 16 个阶段都不知道自己在为哪个画面服务。

**只想先看到东西**：做完 `03a` 阶段 0–3，就能画出第一个精灵。

## 关于"验收不过别往下走"

这不是吓唬人。后面每个阶段都假设前面的东西是对的：

- 阶段 1 的 `pitch` 错了 → 阶段 3 的画面永远是斜的，你会怀疑 SIMD
- 阶段 4 的 `div255` 错了 → 阶段 15 的血条颜色会偏，你找不到原因
- 阶段 5 的 `tpr` 写死 16 → 阶段 16 的 `rift` 地图全是碎片

**每个阶段的验收程序都是独立可编译的**，不要跳过。
走主线时这条同样成立，只是验收对象换成「这一轮下沉后屏幕多了什么」——
见 `从这里开始`「四、每一轮都长这样」，别让一堆能编译的桩冒充进度。
